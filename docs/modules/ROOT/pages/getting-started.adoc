[[neovim]]
== Neovim ≥ 0.12

The system package manager (`apt`, `dnf`, etc.) and Snap often lag behind. Use one of the methods below to get a current release directly from GitHub.

=== AppImage (simplest — runs without installation)

[source,sh]
----
curl -LO https://github.com/neovim/neovim/releases/download/stable/nvim-linux-x86_64.appimage
chmod u+x nvim-linux-x86_64.appimage

# Optional: install system-wide so `nvim` works from anywhere
sudo mv nvim-linux-x86_64.appimage /usr/local/bin/nvim
----

=== Tarball (extract anywhere, no root required)

[source,sh]
----
curl -LO https://github.com/neovim/neovim/releases/download/stable/nvim-linux-x86_64.tar.gz
mkdir -p ~/.local
tar -xzf nvim-linux-x86_64.tar.gz -C ~/.local

# Symlink the binary into a directory on your PATH
ln -sf ~/.local/nvim-linux-x86_64/bin/nvim ~/.local/bin/nvim
----

Make sure `~/.local/bin` is on your `$PATH`:

[source,sh]
----
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
----

=== Verify

[source,sh]
----
nvim --version
# Should show: NVIM v0.12.x or higher
----

[TIP]
====
If you see an older version, run `which nvim` to check which binary is being launched. An old `/usr/bin/nvim` can shadow a new `~/.local/bin/nvim` if PATH order is wrong.
====

[[quick-start]]
== Quick Start

[arabic]
. Clone the repository into your Neovim config directory:
+
[source,sh]
----
git clone https://github.com/floatingman-ltd/arcane-centaur ~/.config/nvim
----
. Launch Neovim:
+
[source,sh]
----
nvim
----
+
https://github.com/folke/lazy.nvim[lazy.nvim] bootstraps itself on first launch and installs all plugins automatically. Wait for the installation to complete, then restart Neovim.
. Verify the install:
+
[source,vim]
----
:checkhealth
----
+
Review any `ERROR` items. `WARN` items for optional features (LSP servers, runtime tools) can be addressed as you enable each language.

[[docker]]
== Docker

Docker Engine and Docker Compose are required by several features:

All nine containerized services, and what each one is for:

[width="100%",cols="30%,30%,40%",options="header",]
|===
|Feature |Docker service |How it is invoked
|AI chat (ollama backend) |Ollama LLM server |`docker/ollama/docker-compose.yml`
|Diagrams |PlantUML server |`docker/plantuml-server/docker-compose.yml`
|Presentations |MARP CLI |`docker/marp/docker-compose.yml`
|Project-wide Markdown preview |markserv |`docker/markserv/docker-compose.yml`
|Common Lisp REPL |SBCL + Swank (default), CCL, ECL, ABCL |`docker/lisp-swank/docker-compose.yml`
|Markdown → PDF export |pandoc + filters |`docker/md2pdf/` (filters, driven by the pandoc wrapper)
|Document conversion |pandoc |`docker/pandoc/run.sh`
|AsciiDoc → HTML (single file) |asciidoctor |`docker/asciidoctor/run.sh`
|Docs site build (this site) |antora |`docker/antora/run.sh`
|===

[NOTE]
====
The last three are `run.sh` wrappers around `docker run`, not Compose services — there is no
container to start and stop. Run them on demand:

[source,sh]
----
./docker/antora/run.sh antora-playbook.yml   # build this documentation site
----
====

=== Installing Docker Engine

Follow the official guide for your platform:

* *Ubuntu / Debian:* https://docs.docker.com/engine/install/ubuntu/
* *Other Linux:* https://docs.docker.com/engine/install/
* *WSL2:* https://docs.docker.com/desktop/windows/wsl/ (Docker Desktop with WSL2 backend)

=== Installing Docker Compose

Docker Compose v2 is included with Docker Desktop and the modern Docker Engine packages. Verify:

[source,sh]
----
docker compose version
# Should output: Docker Compose version v2.x.x
----

If `docker compose` (with a space) is not found, you have the legacy v1 plugin (`docker-compose` with a hyphen). Update to Docker Engine ≥ 20.10 or install the Compose plugin manually — see https://docs.docker.com/compose/install/.

[NOTE]
====
All Docker Compose files in this config use `docker compose` (v2 syntax). The `docker-compose` v1 binary is *not* supported.
====

[[docker-containers]]
=== Docker Containers

Each feature that uses Docker has a dedicated Compose file. Reference this section from the relevant guide rather than duplicating the commands.

[[sbcl-swank]]
==== Common Lisp REPL (lisp-swank)

Compose file: `docker/lisp-swank/docker-compose.yml`

Provides Swank containers for SBCL (default), CCL, ECL, and ABCL. Each starts a Swank server on `127.0.0.1:4005` — the *:4005 contract*: whatever container owns this port is the active Lisp; Conjure always dials 4005 and requires no reconfiguration to switch.

Also exposes `127.0.0.1:8080:8080` for web-service lessons.

[source,sh]
----
# Build all images (required before first use and after pulling config updates):
docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml build

# Start SBCL (default — no profile needed):
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml up -d --wait

# Start a specific implementation (only one at a time):
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml --profile ccl  up -d --wait
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml --profile ecl  up -d --wait
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml --profile abcl up -d --wait

# Switch implementations — bring down the running one, then start the next:
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml down
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml --profile ccl up -d --wait
# Then reconnect Conjure: ,cc

# Stop:
LISP_DIR=$PWD docker compose -f ~/.config/nvim/docker/lisp-swank/docker-compose.yml down
----

NOTE: `LISP_DIR=$PWD` mounts your current working directory into the container so the Lisp implementation can load project files.

[[plantuml-server]]
==== PlantUML Server (Diagrams)

Compose file: `docker/plantuml-server/docker-compose.yml`

Runs a local PlantUML HTTP server. The diagrams plugin sends diagram source to this server and renders the result inline.

[source,sh]

----

[[ollama]]
==== Ollama (AI Chat Backend)

Compose file: `docker/ollama/docker-compose.yml`

Runs a local Ollama LLM server used by Avante and other AI tools for offline model inference.
The compose file starts the server but pulls *no* models — pull the one Avante is configured to
use (see `lua/plugins/avante.lua`) after the container is up, or Avante's default provider will
connect but return nothing. Avante defaults to the small `qwen2.5:0.5b` (~0.4 GB) for very-limited-RAM
machines; bump to `llama3.2:1b` (~1.3 GB) or `llama3.2:3b` and set the matching `model` in the config.

[source,sh]
----
docker compose -f ~/.config/nvim/docker/ollama/docker-compose.yml up -d
# Pull the model Avante's default (ollama) provider expects. Pull through Ollama's HTTP API
# rather than `docker compose exec` — exec sets up a runc console socket that fails on some
# hosts with "failed to create runc console socket: … read-only file system"; the API call
# talks straight to the running server and sidesteps it:
curl http://127.0.0.1:11434/api/pull -d '{"name":"qwen2.5:0.5b"}'
# Confirm it is served on the endpoint Avante uses:
curl -s http://127.0.0.1:11434/api/tags   # should list qwen2.5:0.5b
docker compose -f ~/.config/nvim/docker/ollama/docker-compose.yml down
----

TIP: If the *container itself* won't start, fix Docker rather than bypassing it — this config keeps
Ollama and the other services containerized on purpose. A fresh `docker run --rm alpine sh -c 'touch
/t'` that fails with `read-only file system` points at Docker's storage/overlay layer.

[[system-deps]]
[[required-everyone]]
== Required for everyone

Install these before first launch. Without them the config either fails to install plugins or
loses core editing functionality.

[source,sh]
----
sudo apt install -y \
  build-essential \
  git \
  curl \
  unzip \
  lua5.4 \
  luarocks \
  ripgrep \
  fzf
----

[cols="1,2"]
|===
|Package |Why it's needed
|`build-essential` |A C compiler — *compiles Treesitter parsers*, plus native plugin components
|`git` |lazy.nvim fetches plugins via git
|`curl` |Used by install scripts and plugin build steps
|`unzip` |Needed to extract some plugin archives
|`lua5.4` |Required by lazy.nvim's LuaRocks support
|`luarocks` |Plugin dependency manager used by lazy.nvim
|`ripgrep` |Backs the fuzzy picker's live grep, todo-comments, and trouble
|`fzf` |Backs fzf-lua — the picker used for files, buffers, and symbols
|===

[[c-compiler]]
=== C compiler (build-essential)

Treesitter parsers are *compiled from source on your machine* at install time, so a working
`cc`/`gcc` is required for syntax highlighting, indentation, and the `af`/`if` text objects in
every supported language.

[IMPORTANT]
====
A missing C compiler *fails silently*. Parser installation aborts, and the only symptom is a file
with no syntax highlighting — no error, no notification, nothing in `:messages`. If highlighting
is missing for one language, check the compiler before anything else.
====

[source,sh]
----
sudo apt install -y build-essential   # Debian/Ubuntu
cc --version                          # verify
----

Then confirm the parsers actually built:

[source,vim]
----
:checkhealth nvim-treesitter
----

See xref:languages/setup.adoc#parsers[Language Setup → Treesitter parsers] for the full parser list.

[[editor-binaries]]
=== ripgrep and fzf

These two are easy to overlook because nothing errors without them — the config just quietly
loses its core navigation UX.

[cols="1,2"]
|===
|Binary |What breaks without it
|`rg` (ripgrep) |Live grep in the picker, the todo-comments list (`++<++leader++>++xT`), and trouble's search
|`fzf` |fzf-lua itself — the picker used for files, buffers, git files, and symbols
|===

[source,sh]
----
sudo apt install -y ripgrep fzf     # Debian/Ubuntu
# or: brew install ripgrep fzf
----

[[claude-cli]]
=== claude CLI (AI features)

Three separate features shell out to the `claude` binary, so without it none of the AI integration
works:

[cols="1,2"]
|===
|Feature |Entry points
|`claude_cli` |`:ClaudeSuggest` / `:ClaudeExplain` — `++<++leader++>++gcs` / `++<++leader++>++gce`
|claudecode.nvim |The persistent editor-aware session — `++<++leader++>++gcc`
|Research popup |`:ResearchLocal` / `:ResearchAsk` — `++<++leader++>++?l` / `++<++leader++>++?a`
|===

Install Claude Code and make sure `claude` is on your `$PATH`:
https://docs.claude.com/en/docs/claude-code/overview[Claude Code documentation].

[WARNING]
====
These features authenticate through Claude Code itself. They do *not* use `ANTHROPIC_API_KEY` —
and a stray `ANTHROPIC_API_KEY` in your environment actively breaks `claude_cli`. Unset it if the
commands start failing.
====

[[nodejs]]
=== Node.js and npm

Required by the build steps of *two* plugins — `markdown-preview.nvim` and `bracey.vim` (live HTML
preview). Both fail to build without it.

Use https://github.com/nvm-sh/nvm[nvm] to install Node.js without root:

Use https://github.com/nvm-sh/nvm[nvm] to install Node.js without root:

[source,sh]
----
# Install nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc

# Install and use the LTS release
nvm install --lts
nvm use --lts
nvm alias default lts/*

# Verify
node --version
npm --version
----

=== Universal Ctags (optional — enables tag navigation)

A *soft dependency*: nothing in the configuration invokes it, but installing
https://github.com/universal-ctags/ctags[universal-ctags] lets you generate a `tags` index so
Vim's tag navigation works — `]t` / `[t` (vim-unimpaired) and `<C-]>` (jump to definition). Without
a `tags` file those maps simply have nothing to jump to; they do not error.

[source,sh]
----
sudo apt install universal-ctags   # Debian/Ubuntu; or: brew install universal-ctags

# Generate the index at the project root (the generated `tags` file is gitignored)
ctags -R
----

=== Git Blame Configuration (optional)

The repo carries a `.git-blame-ignore-revs` file listing mechanical reformat commits (e.g. the
tree-wide stylua normalization) so `git blame` attributes reformatted lines to their real
authoring commit instead of the formatter run. GitHub honors this file automatically; locally,
opt in once per clone:

[source,sh]
----
git config blame.ignoreRevsFile .git-blame-ignore-revs
----

Without this, `git blame` (and editor blame integrations) will show the reformat commit for
every line it touched.

[[wsl]]
== WSL

Running under WSL2 adds two host-integration binaries the config probes for. Neither is fatal, but
both affect everyday use.

[cols="1,2,2",options="header"]
|===
|Binary |Purpose |Install
|`win32yank.exe` |Clipboard integration — yanking to and from the Windows clipboard |https://github.com/equalsraf/win32yank/releases[GitHub release]; put it on your `$PATH` inside WSL
|`wslview` |Opens URLs in your Windows browser |`sudo apt install -y wslu` — optional
|===

`wslview` is a convenience rather than a requirement. `util.open_url` tries it first under WSL, then falls back to `explorer.exe`, which is always present and reaches the same Windows browser — including when WSLg is not running and no `$DISPLAY` is exported. Either way the URL is also copied to the clipboard and echoed to the command line, so it stays recoverable from `:messages`.

Without `win32yank.exe`, Neovim's clipboard provider has nothing to bridge to Windows; see xref:editor/clipboard.adoc[the Clipboard guide] for the per-environment provider setup.

== Troubleshooting

=== lazy.nvim fails to install plugins

Check that `git` and `curl` are installed and that you have internet access. Run `:Lazy` inside Neovim to see the plugin install log.

=== `:checkhealth` shows clipboard errors

See the xref:editor/clipboard.adoc[Clipboard guide] for provider setup per environment (GUI Linux, WSL, SSH/TTY).

=== A plugin requires a build step that fails

Most build failures are caused by missing `build-essential` or `node`. Install the system deps above and run `:Lazy build <plugin-name>` to retry.
