== AsciiDoc Authoring Guide

AsciiDoc/Antora is the **source of truth** for all documentation in this
configuration. Files live under `docs/modules/ROOT/pages/`. The nav entry
point is `docs/modules/ROOT/nav.adoc`.

→ xref:content/asciidoc-cheatsheet.adoc[AsciiDoc Cheatsheet]

'''''

== Filetype

All `.adoc`, `.asciidoc`, and `.asciidoctor` files resolve to the canonical
filetype **`asciidoctor`** (registered via `vim.filetype.add` in
`lua/plugins/asciidoc.lua`). This is the filetype vim-asciidoctor expects
and the key all buffer-local keymaps are registered under.

'''''

== Syntax, Folding, and Fenced-Code Highlighting

Powered by **`habamax/vim-asciidoctor`**, which provides:

- Faster, more accurate AsciiDoc syntax highlighting than Neovim's built-in
  regex highlighter.
- Section folding — `za`/`zc`/`zo`/`zM`/`zR` (standard Neovim fold keys).
- Fenced-code-block highlighting: a `[source,lua]` block is highlighted as
  Lua, and so on for `bash`, `python`, `clojure`, `haskell`.

Markup conceal is intentionally **off** (`asciidoctor_syntax_conceal = 0`)
so raw markup stays visible while editing. There is no in-buffer rendered view:
markview.nvim is deferred until a tree-sitter AsciiDoc grammar is available.

=== Supported fenced languages

`lua`, `bash`, `python`, `clojure`, `haskell`

`[source,fsharp]` blocks are not highlighted: Vim ships no `syntax/fsharp.vim`, and
vim-asciidoctor fails with `E484` on every `.adoc` open if a listed language has none.
Add others by extending `asciidoctor_fenced_languages` in
`lua/plugins/asciidoc.lua`.

[[vim-asciidoctor-commands]]
=== vim-asciidoctor commands

vim-asciidoctor defines these buffer-local commands in every `.adoc`
buffer. They are *not* disabled: `asciidoctor_extensions = {}` only means
no `-r` extension is passed to `asciidoctor`. They have no keymaps.

[cols="2,3",options="header"]
|===
|Command |Action

|`:Asciidoctor2HTML`
|Run `asciidoctor` on the file through `:make`, writing `++<name>.html++` next to it

|`:Asciidoctor2PDF`
|Run `asciidoctor-pdf` the same way, writing `++<name>.pdf++`

|`:Asciidoctor2DOCX`
|Run `asciidoctor -b docbook` to write `++<name>.xml++`, then `pandoc` to convert it to `++<name>.docx++`

|`:AsciidoctorOpenHTML` / `:AsciidoctorOpenPDF` / `:AsciidoctorOpenDOCX`
|Open the `.html` / `.pdf` / `.docx` with the same base name, already beside the file; prints `doesn't exist!` if it is not there

|`:AsciidoctorOpenRAW`
|Open the `.adoc` file itself with the system's default application

|`:AsciidoctorPasteImage`
|Save the clipboard image as `++img_<name>_<n>.png++` in the `:imagesdir:` directory (or the file's directory if none is set) and insert an `image::` line below the cursor
|===

[WARNING]
====
These commands call native tools that this config does not install and
does not list as prerequisites — the Docker preview below is the supported
route:

* `:Asciidoctor2HTML` and `:Asciidoctor2DOCX` need `asciidoctor` on
  `$PATH`; `:Asciidoctor2PDF` needs `asciidoctor-pdf`; `:Asciidoctor2DOCX`
  also needs `pandoc`. Without them `:make` puts
  `command not found: asciidoctor` in the quickfix list and writes nothing.
* `:AsciidoctorPasteImage` runs `gm convert clipboard:` (GraphicsMagick).
  The plugin marks this Linux default as a placeholder, and `gm` is not
  a prerequisite of this config. Set `g:asciidoctor_img_paste_command` to a working command
  before relying on it.
* The `Open` commands do not find Docker preview output: `,p` writes its
  HTML to `~/.cache/nvim/asciidoc-preview/`, not beside the source. The
  `Open` commands use `xdg-open`, or `cmd.exe /C start` under WSL.
====

== Preview

=== Single-page preview (Docker)

`<localleader>p` / `<localleader>pp` — converts the current `.adoc` buffer to
HTML using the `asciidoctor/docker-asciidoctor` image and opens it in the
system browser.

Requires Docker running and a graphical environment. In SSH/headless sessions
a warning is shown instead.

=== Full Antora site preview (Docker)

`<localleader>pa` — builds the complete Antora site from
`antora-playbook-local.yml` (reads the working tree, not the remote Git
source) and opens `build/site/index.html`. This resolves cross-page `xref:`
links, includes, and the full nav — the closest production-equivalent preview.

Build output goes to `build/site/` (gitignored).

'''''

== Shell Build

To build the Antora site from the terminal (requires Docker):

[source,sh]
----
./docker/antora/run.sh antora-playbook.yml
----

Output goes to `build/site/` (gitignored).
