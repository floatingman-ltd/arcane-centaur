== gitsigns.nvim

Shows you what you changed, as you change it. Gitsigns marks every added, edited, or deleted line
in the narrow column to the left of your code, so the shape of your edit is visible without
running any command. You can then act on one change at a time — stage it, undo it, or peek at what
the line looked like before — without staging the whole file.

This is the close-range tool: use it while you are actually typing. For the full repository
picture and for writing the commit, see xref:editor/git/vim-fugitive.adoc[vim-fugitive].

A *hunk* is just one contiguous block of changed lines. Most of the keymaps below act on the hunk
your cursor is sitting in.

The signs in the left column mean:

* `▎` added
* `▎` changed
* `▁` / `▔` deleted line

=== Hunk navigation

[cols="1,1,2",options="header"]
|===
|Keys |Mode |Action
|`++]++h` |Normal |Jump to next hunk
|`++[++h` |Normal |Jump to previous hunk
|===

=== Hunk actions

[cols="1,1,2",options="header"]
|===
|Keys |Mode |Action
|`++<++leader++>++hs` |Normal, Visual |Stage hunk (or selected lines)
|`++<++leader++>++hr` |Normal, Visual |Reset hunk (or selected lines)
|`++<++leader++>++hS` |Normal |Stage entire buffer
|`++<++leader++>++hR` |Normal |Reset entire buffer
|`++<++leader++>++hu` |Normal |Undo last stage
|`++<++leader++>++hp` |Normal |Preview hunk in a float
|`++<++leader++>++hb` |Normal |Full blame for current line
|`++<++leader++>++hd` |Normal |Diff this file (unstaged)
|`++<++leader++>++hD` |Normal |Diff this file against the commit before HEAD (`HEAD~`)
|===

In Visual mode, only the lines inside your selection are staged or reset — which is how you commit
half of a messy change and leave the rest.

=== Text object

[cols="1,1,2",options="header"]
|===
|Keys |Mode |Action
|`++<++leader++>++ih` |Visual, Operator |Select current hunk
|===

Because it is a text object it composes with ordinary operators — `d++<++leader++>++ih` deletes
the hunk, `y++<++leader++>++ih` yanks it.

____
*Note — Haskell buffers:* `++<++leader++>++hs` is used by haskell-tools for Hoogle search in
`.hs` files. The buffer-local Haskell binding wins there, so stage from the fugitive status window
(`:Git`) instead while editing Haskell.
____

=== The `:Gitsigns` command

Every keymap above calls a gitsigns function, and `:Gitsigns \{subcommand} \{args}` calls the same
functions by name. Use it for the actions that have no keymap here. `:Gitsigns ++<++Tab++>++`
completes the subcommand names; `:Gitsigns` on its own opens a picker of them.

[cols="1,2",options="header"]
|===
|Command |Action
|`:Gitsigns blame_line` |Blame for the current line in a float. `++<++leader++>++hb` adds
`--full`, which shows the whole commit message and the hunk.
|`:Gitsigns blame` |Blame the whole file in a scroll-bound vertical split.
|`:Gitsigns toggle_current_line_blame` |Toggle end-of-line blame text on the cursor line. Off by
default.
|`:Gitsigns preview_hunk` |Show the hunk under the cursor in a float (as `++<++leader++>++hp`).
|`:Gitsigns preview_hunk_inline` |Show the hunk's removed lines inline in the buffer.
|`:Gitsigns stage_hunk` / `reset_hunk` |Stage / reset the hunk under the cursor. With a range,
e.g. `:'++<++,'++>++Gitsigns stage_hunk`, only those lines.
|`:Gitsigns diffthis \{base}` |Diff the file against `\{base}` in a split. No `\{base}` diffs
against the index; `@` against `HEAD`; `~` against the commit before `HEAD` (gitsigns reads a
leading `~` as `HEAD~`).
|`:Gitsigns change_base \{rev}` |Draw the signs against `\{rev}` instead of the index, e.g.
`HEAD~3`. `:Gitsigns reset_base` goes back to the index.
|`:Gitsigns setqflist all` |List the hunks of every modified file in the repository in the
quickfix list and open it. No argument lists the current buffer only.
|`:Gitsigns toggle_word_diff` |Highlight changed words inside changed lines.
|`:Gitsigns toggle_linehl` / `toggle_numhl` |Toggle highlighting of changed lines / of their line numbers.
|`:Gitsigns toggle_signs` |Hide or show the signs column.
|===

`true`, `false`, `nil` and numbers are passed as Lua values, so
`:Gitsigns toggle_current_line_blame true` sets the value instead of toggling it. The full
function list is in `:help gitsigns-functions`.

=== Setup

None. Gitsigns attaches by itself to any file inside a git repository, and stays out of the way in
files that are not tracked.
