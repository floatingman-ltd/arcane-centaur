== Language Setup

Everything you need to install *per language*, in one place. Working with C#? Install the four
tools in the xref:#dotnet[.NET] section. Working with Lisp? The xref:#lisp[Lisp family] section.
Nothing here is needed until you actually open a file of that type — the config lazy-loads all
language tooling by filetype.

Base tools that *every* language needs — Neovim, git, curl, a C compiler, and the editor binaries
`rg` and `fzf` — live in xref:getting-started.adoc[Getting Started]. Install those first.

[[lua]]
== Lua

Guide: xref:languages/lua.adoc#prerequisites[Lua Prerequisites]

[cols="1,1,2",options="header"]
|===
|Dependency |Purpose |Install
|*lua-language-server* |LSP — completion, diagnostics, go-to-definition |https://github.com/LuaLS/lua-language-server/releases[GitHub release] (or `brew install lua-language-server`)
|*stylua* |Formatter |`cargo install stylua` — or a https://github.com/JohnnyMorganz/StyLua/releases[GitHub release] binary
|===

[IMPORTANT]
====
`stylua` is *required, not optional*, for Lua work in this repo. It is load-bearing twice over:
conform's format-on-save uses it, and a `PostToolUse` hook re-runs it on every Lua file Claude
Code edits, so the committed tree stays stylua-clean.

It degrades gracefully — a missing `stylua` means formatting simply does not apply. Edits are
never blocked and nothing errors.
====

[[dotnet]]
== .NET (C# and F#)

Guide: xref:languages/dotnet.adoc#prerequisites[.NET Prerequisites]

[cols="1,1,2",options="header"]
|===
|Dependency |Purpose |Install

|*.NET SDK*
|Compiler, `dotnet fsi`, and the `dotnet tool` host everything else installs through
|https://dotnet.microsoft.com/download[Microsoft download page]

|*Microsoft.CodeAnalysis.LanguageServer*
|C# LSP (Roslyn), driven by roslyn.nvim
|Must be on `$PATH` — see xref:languages/dotnet.adoc#prerequisites[the .NET guide]

|*fsautocomplete*
|F# LSP; drives F# formatting, but delegates the formatting itself to Fantomas
|`dotnet tool install -g fsautocomplete`

|*fantomas*
|F# formatter. Required for F# format-on-save — without it fsautocomplete raises an interactive install prompt on every write
|`dotnet tool install -g fantomas`

|*csharprepl*
|C# REPL, driven by iron.nvim
|`dotnet tool install -g csharprepl`

|*csharpier*
|C# formatter
|`dotnet tool install -g csharpier`

|*EasyDotnet*
|Server tool that easy-dotnet.nvim requires for solution management, run, and test
|`dotnet tool install -g EasyDotnet`

|*netcoredbg*
|Debug adapter, auto-registered with nvim-dap by easy-dotnet
|A https://github.com/Samsung/netcoredbg/releases[GitHub release] binary — *not* a `dotnet tool`
|===

[WARNING]
====
`netcoredbg` is the one .NET tool you cannot get with `dotnet tool install`. Download the release
archive for your platform and put the binary on `$PATH`.
====

[[haskell]]
== Haskell

Guide: xref:languages/haskell.adoc#prerequisites[Haskell Prerequisites]

[cols="1,1,2",options="header"]
|===
|Dependency |Purpose |Install

|*ghcup*
|Installer that manages every other Haskell tool
|https://www.haskell.org/ghcup/[ghcup]

|*GHC {plus} cabal / stack*
|Compiler and build tooling; GHCi is the REPL
|`ghcup install ghc` and `ghcup install cabal`

|*haskell-language-server*
|LSP, driven by haskell-tools.nvim (not `lua/config/lsp.lua`)
|`ghcup install hls`

|*haskell-debug-adapter*
|Debug adapter for nvim-dap
|`cabal install haskell-dap ghci-dap haskell-debug-adapter`
|===

[NOTE]
====
Haskell debugging needs *both* `haskell-debug-adapter` **and** an open cabal or stack project.
haskell-tools.nvim registers `require("dap").configurations.haskell` only when it detects a
project, so on a bare `.hs` file the debug configuration list stays empty even with the adapter
installed. This is why the Haskell debugging validation step (`§7.5` in
`openspec/TEST_PLAN.md`) is deferred rather than failing.
====

[[markdown]]
== Markdown

Guide: xref:editor/code-intelligence.adoc[Code Intelligence]

[cols="1,1,2",options="header"]
|===
|Dependency |Purpose |Install
|*marksman* _(optional)_ |LSP server — hover, go-to-definition, references, rename, document symbols, code actions, completion |https://github.com/artempyanykh/marksman/releases[GitHub release binary] → `~/.local/bin`

`marksman` supplies no folding ranges and no formatting. Markdown folds come from treesitter with an indent fallback, and no LSP-backed markdown formatter is configured — installing the server deliberately changes neither.

[[parsers]]
== Treesitter parsers

Syntax highlighting, indentation, and the `af`/`if` text objects all come from Treesitter, and
*parsers are compiled from source on your machine*. That means a working C compiler is a hard
requirement for every language in the table above.

If `cc`/`gcc` is missing, parser installation fails and the only symptom you see is a file with
no syntax highlighting — nothing announces the missing compiler. See
xref:getting-started.adoc#c-compiler[Getting Started → C compiler] for the install command and
how to verify.

The config installs these parsers automatically on first launch: `commonlisp`, `clojure`,
`scheme`, `fennel`, `janet_simple`, `lua`, `fsharp`, `c_sharp`, `haskell`, `vim`, `http`,
`markdown`, and `markdown_inline`. Check the result with:

[source,vim]
----
:checkhealth nvim-treesitter
----
