== Working with Haskell

Haskell support is provided by
https://github.com/mrcjkb/haskell-tools.nvim[haskell-tools.nvim], which
bundles LSP integration, a GHCi REPL, and Hoogle search into a single
plugin.

All Haskell plugins lazy-load only when you open a `.hs` or `.lhs` file.

[[quick-start]]
== Quick Start

[arabic]
. Install GHC and haskell-language-server via `ghcup` (see
xref:#prerequisites[Prerequisites]).
. Open a Haskell source file — plugins load automatically:
+
[source,sh]
----
nvim src/Main.hs
----
. Press `++<++leader++>++rr` to open a GHCi REPL for the current package.
. Evaluate code in the REPL, or press `++<++leader++>++rf` to open a
file-scoped REPL.

'''''

[[lsp]]
== LSP

`haskell-tools` manages the `hls` LSP connection automatically — no
manual `lspconfig` setup is needed. See the
xref:editor/code-intelligence.adoc[Code Intelligence cheatsheet] for
shared LSP keybindings (`gd`, `K`, `gr`, etc.).

`:Hls` controls the language server client. `:Hls <Tab>` offers only `start` when no
HLS client is attached to the buffer, and `stop`, `restart`, `evalAll` when one is.

[cols="1,2",options="header"]
|===
|Command |Action
|`:Hls start` |Start HLS for the current buffer
|`:Hls stop` |Stop HLS for the current buffer
|`:Hls restart` |Restart HLS for the current buffer
|`:Hls evalAll` |Run every HLS eval code lens (`-- >>>` snippets in comments); same as
`Space-ea`
|===

'''''

[[repl]]
== REPL (GHCi)

haskell-tools provides a built-in GHCi REPL. Keybindings are defined in
`after/ftplugin/haskell.lua`.

Leader is `Space`; no LocalLeader bindings are used in Haskell buffers.

[cols=",",options="header",]
|===
|Keys |Action
|`++<++leader++>++rr` |Toggle GHCi REPL for the current package
|`++<++leader++>++rf` |Toggle GHCi REPL for the current file
|`++<++leader++>++rq` |Quit the GHCi REPL
|`Space-cl` |Run code lenses (haskell-language-server)
|`Space-hs` |Hoogle search for type under cursor
|`Space-ea` |Evaluate all code snippets in the buffer
|===

[[commands]]
=== Commands

`:Haskell` takes a subcommand; `:Haskell <Tab>` completes them. Both `:Haskell` and
`:Hls` (see xref:#lsp[LSP]) are created when the first Haskell buffer opens. Neither
waits for HLS to attach, and the `repl`, project-file and `log` subcommands work with
no language server running.

[cols="1,2",options="header"]
|===
|Command |Action
|`:Haskell repl toggle [file]` |Toggle a GHCi REPL loaded with `file` (default: the
current buffer); same as `++<++leader++>++rf`
|`:Haskell repl quit` |Quit the REPL; same as `++<++leader++>++rq`
|`:Haskell repl load [file]` |Load `file` (default: the current buffer) into the
running REPL
|`:Haskell repl reload` |Send `:r` to the REPL
|`:Haskell repl cword_type` |Ask the REPL for the type of the word under the cursor
|`:Haskell repl cword_info` |Ask the REPL for info on the word under the cursor
|`:Haskell repl paste_type [reg]` |Ask the REPL for the type of the contents of
register `reg` (default: `"`)
|`:Haskell repl paste_info [reg]` |Ask the REPL for info on the contents of register
`reg` (default: `"`)
|`:Haskell projectFile` |Open the project file (`cabal.project` or `stack.yaml`)
|`:Haskell packageCabal` |Open the package's `*.cabal` file
|`:Haskell packageYaml` |Open the package's `package.yaml`
|`:Haskell log setLevel \{level}` |Set the haskell-tools and LSP client log level
(`TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`, `OFF`)
|`:Haskell log openLog` |Open the haskell-tools log file
|`:Haskell log openHlsLog` |Open the haskell-language-server log file
|===

There is no command form of `++<++leader++>++rr` (package-scoped REPL); `:Haskell repl
toggle` always passes a file.

'''''

== Debugging

https://github.com/MrcJkb/haskell-tools.nvim[haskell-tools.nvim] auto-discovers
DAP launch configurations once https://github.com/mfussenegger/nvim-dap[nvim-dap]
is installed (added in change 07 for .NET debug support).

Use the standard debug keymaps (`<F5>`, `<F9>`, `<F10>`/`<F11>`/`<F12>`) to start
a session. The `:Dap*` commands (`:DapContinue`, `:DapToggleBreakpoint`,
`:DapClearBreakpoints`, …) also work here; opening a Haskell buffer loads nvim-dap, so
they exist from then on. The full table is in the
xref:languages/dotnet.adoc#dap-commands[.NET guide].

[IMPORTANT]
====
Haskell debugging needs *two* things, and both must be present before any debug configuration
appears:

. **`haskell-debug-adapter` installed** — `cabal install haskell-dap ghci-dap haskell-debug-adapter`
. **An open cabal or stack project** — haskell-tools.nvim registers
  `require("dap").configurations.haskell` only when it detects project files

On a bare `.hs` file with no project, the configuration list stays *empty* even with the adapter
installed, and `<F5>` has nothing to launch. This is why the Haskell debugging validation step
(`§7.5` in `openspec/TEST_PLAN.md`) is deferred rather than failing.
====

'''''

Haskell-specific tools only. Base requirements — Neovim itself, git, a C compiler for the

|*haskell-language-server* |LSP server |`ghcup install hls`

|*haskell-debug-adapter* |Debug adapter for nvim-dap — also requires an open cabal/stack project
