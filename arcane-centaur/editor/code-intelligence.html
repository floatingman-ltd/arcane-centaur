Keymaps defined in lua/config/lsp.lua.

marksman supplies hover, go-to-definition, references, rename, document symbols, code actions and completion — but not folding ranges or formatting. Markdown folds come from treesitter with an indent fallback (see Navigation), and no LSP-backed markdown formatter is configured.

fsautocomplete supplies all of the above plus folding ranges, signature help and formatting, so F# gains LSP folds and format-on-save. It does not supply indentation: F# has no indent script and no treesitter indents.scm, so pressing Enter copies the previous line’s indent rather than indenting the body. That gap is tracked separately.

Formatting needs a second binary: fsautocomplete delegates it to Fantomas and does not ship it. Without fantomas on $PATH the write does not silently skip formatting — the server raises an interactive No Fantomas install was found. prompt that blocks every save of an F# buffer. Install it with dotnet tool install -g fantomas.

fsautocomplete also cannot answer for a bare .fs file that sits outside any project: such a file is never added to its loaded projects, so requests fail with Couldn’t find <path> in LoadedProjects and opening one is enough to log an UnhandledPromiseRejection. Work inside a project, or use a .fsx script, which it resolves on its own.

Using the panel

Every <leader>x* map is a toggle: press it once to open the panel, again to close it. Inside the panel, j/k move between entries, Enter jumps to the location under the cursor (the panel stays open), q closes the panel, and ? lists every in-panel keybinding (preview, fold, filter, delete, …).

Pick the source for the job:

Panel What it shows

Project diagnostics (<leader>xx)

Every LSP warning/error across the whole workspace

Buffer diagnostics (<leader>xX)

Diagnostics for the current file only

Symbols (<leader>xs)

Outline of the current file (functions, classes, …); opens to the side and leaves the cursor in your code

LSP refs/defs (<leader>xr)

References and definitions of the symbol under the cursor, in a right-hand panel

Location list (<leader>xl)

The current window’s location list

Quickfix (<leader>xq)

The quickfix list — fill it first with gr, :grep, :make, or :lua vim.diagnostic.setqflist()

Todo comments (todo-comments.nvim)

todo-comments.nvim highlights annotation keywords in your comments — coloured text plus a sign in the gutter — and can list them across the whole project. A keyword is only recognised when written with a trailing colon (TODO:) inside a comment.

Keyword Aliases (same colour)

—

FIXME: BUG: FIXIT: ISSUE:

HACK:

—

WARN:

WARNING: XXX:

PERF:

OPTIM: PERFORMANCE: OPTIMIZE:

NOTE:

INFO:

TEST:

TESTING: PASSED: FAILED:

Two list views scan the whole project for these markers:

  • <leader>xt (:TodoTrouble) — todos in a Trouble panel, navigated exactly like the panels above.

  • <leader>xT (:TodoFzfLua) — todos in an fzf-lua fuzzy picker; type to filter, Enter to jump.

Both views search with ripgrep, so rg must be on your PATH; the fzf-lua view additionally needs the fzf binary. If either is missing the map reports it (rg was not found / 'fzf' not installed) rather than listing todos.
[d/]d and <leader>e (LSP diagnostics float) are unchanged. ]t/[t are tag navigation, covered in Tag Navigation (ctags) below.

Configured in lua/plugins/trouble.lua and lua/plugins/todo-comments.lua.

Tag Navigation (ctags)

A tags file is an index — generated by universal-ctags — that maps every symbol name to the file and line where it is defined. It gives cross-file "jump to definition" in any language with no language server involved, and it is what makes the ]t/[t maps do anything.

Generate the index at the project root (Neovim finds ./tags automatically). The index is a static snapshot, so re-run this after significant edits:

ctags -R          # writes ./tags (gitignored)

universal-ctags is a soft dependency — see System Dependencies to install it.

Keys Action

Ctrl-]

Jump to the definition of the tag under the cursor

g Ctrl-]

Same, but list the matches to choose from when there are several (:tjump)

Ctrl-o

Jump back to where you came from (the jump list)

]t / [t

Next / previous match when a tag has several definitions (vim-unimpaired → :tnext / :tprevious)

]T / [T

Last / first match (:tlast / :tfirst)

:tag {name}

Jump to a named tag; :tag /pat jumps to the first tag matching a pattern

:tselect {name}

List all matching tags and pick one
]t/[t only move when the current tag has more than one definition — with a single match there is nothing to cycle to (you may see E428/E425 at the list ends, which is normal). In LSP buffers, gd (go to definition) is usually the better tool and needs no tags file.
Vim’s built-in Ctrl-t (pop the tag stack) is remapped in this configuration to toggle the file tree (:NvimTreeToggle). To step back after a tag jump use Ctrl-o or :pop instead.

`]t`/[t/]T/[T come from tpope/vim-unimpaired; Ctrl-], g Ctrl-], and Ctrl-o are Vim built-ins.

Auto-Completion (blink.cmp)

Powered by blink.cmp v1 — a Rust-based fuzzy completion engine with sub-millisecond latency. Replaces nvim-cmp.

Completion Menu

Enter does not accept a completion. Accept with Ctrl-y. Enter always inserts a newline in insert mode and executes the command on the command line, whether or not the menu is open and whether or not an entry is highlighted. If you are used to Enter confirming a suggestion, this is the one key you have to relearn.

There is a single completion keymap, and it behaves identically in insert mode and on the command line. Previously the two were configured separately and disagreed about which key accepted.

Keys Mode Action

Ctrl-n

Insert / Command-line

Open the completion menu when it is closed; select the next suggestion when it is already open

Ctrl-p

Insert / Command-line

Select previous suggestion

Ctrl-y

Insert / Command-line

Accept the highlighted suggestion, or the top one if none is highlighted

Ctrl-e

Insert / Command-line

Cancel — dismiss the menu and restore the text you typed

Ctrl-k

Insert / Command-line

Show the documentation window for the selected entry

Ctrl-f

Insert / Command-line

Scroll documentation preview down

Ctrl-b

Insert / Command-line

Scroll documentation preview up

The trigger key

Ctrl-n does double duty: it is the manual trigger and the select-next key. With the menu closed it opens it; with the menu already open it walks down the list.

In practice the menu is usually already open, because it auto-shows the moment you type a keyword (show_on_keyword). So while typing a word, the first Ctrl-n selects the first entry. You only see the trigger role when the menu is genuinely closed — after dismissing it with Ctrl-e, or when the cursor is not in a keyword at all.

Either way nothing is highlighted when the menu appears (preselect = false), so a completion is never committed implicitly. Only an explicit Ctrl-y inserts anything.

This mirrors what insert-mode Ctrl-n already means in stock Vim.

There is no Alt-Space trigger, despite what older revisions of these docs said. This configuration runs under WSL in a Windows console, which claims Alt-Space for its own system menu, so the keystroke never reached Neovim. Ctrl-Space is swallowed the same way. Any manual trigger here has to be a plain Ctrl-plus-letter chord.

The documentation window

Selecting an entry shows a documentation window beside the menu after a short delay (500ms). Ctrl-f and Ctrl-b scroll it, four lines at a time.

Two things make this less visible than you might expect. The window is 20 rows tall, and the scroll keys clamp to the content, so a docstring that already fits will not appear to move at all — the keys are working, there is simply nothing to scroll. And the window only renders what the language server actually sends: an entry with neither detail nor documentation closes it silently.

lua_ls supplies neither field on its completion entries, so the documentation window never appears in Lua buffers, whatever you press. C# via roslyn is the reliable place to see it. Since this configuration is mostly Lua, expect the window less often than these keys suggest.

If the automatic window gets in the way, turn it off for the session:

:BlinkDocsToggle

That switches between timed (the window appears on its own) and on-demand (it appears only when you press Ctrl-k), reporting the new state. It is not persisted — every session starts timed. Ctrl-k works in both modes, and needs an entry already selected, so it is Ctrl-n then Ctrl-k. A window that is already open when you switch to on-demand keeps following your selection until the menu closes.

Ctrl-n in normal mode is unrelated — it opens the file tree. The completion keymap only binds insert and command-line modes.

Command-line Completion

Mode Sources

/ / ? search

Buffer words

: commands

File paths, then Ex commands

The menu appears on its own at these prompts (auto_show), so you usually will not need the trigger. The keys are the same as insert mode — Ctrl-y accepts, Ctrl-n/Ctrl-p walk the list, Ctrl-e cancels, Ctrl-k shows documentation — and Enter executes the command line as always. Completing a command is therefore :Blin Ctrl-n Ctrl-y.

Ctrl-k is bound here as well, because the command line uses the same keymap table, but in practice it has nothing to show: command-line candidates carry only the short grey description rendered inline in the menu, not the detail or documentation fields the window renders. It is harmless — it will not disturb what you have typed — but do not expect a documentation window at the : prompt.

Command-line history is on Up and Down, not Ctrl-p/Ctrl-n — and they are the better keys for it, since they recall only entries matching what you have already typed. Ctrl-n/Ctrl-p belong to the completion menu.

You may notice Ctrl-p recalling history on an empty command line. That is the fallback entry doing its job: with no menu open there is nothing to select, so the key does whatever Neovim natively does with it. Ctrl-n does not behave symmetrically, because it carries the trigger role — show succeeds and opens the menu, so it never reaches the fallback. The fallback rule is the same in both modes; only Neovim’s native meaning differs (history on the command line, keyword completion in insert mode).

Tab does not select items in blink’s menu here. blink’s stock command-line preset used it, but this configuration uses the shared keymap instead so that insert mode and the command line cannot drift apart. Tab therefore falls back to Neovim’s own wildmenu, which is still perfectly usable — wildmode=full completes to the first full match and further presses cycle through the rest. It is deliberately left alone rather than rebound, because wildmenu Tab exists only on the command line: a habit built on it would fail in insert mode, which is the exact drift this keymap sets out to remove. Use Ctrl-n if you want one key that behaves the same in both places.

Configured in lua/plugins/blink.lua. LSP capabilities wired in lua/config/lsp.lua.
