Language Setup

Everything you need to install per language, in one place. Working with C#? Install the four tools in the .NET section. Working with Lisp? The Lisp family section. Nothing here is needed until you actually open a file of that type — the config lazy-loads all language tooling by filetype.

Base tools that every language needs — Neovim, git, curl, a C compiler, and the editor binaries rg and fzf — live in Getting Started. Install those first.

Lua

Guide: Lua Prerequisites

Dependency Purpose Install

lua-language-server

LSP — completion, diagnostics, go-to-definition

GitHub release (or brew install lua-language-server)

stylua

Formatter

cargo install stylua — or a GitHub release binary

stylua is required, not optional, for Lua work in this repo. It is load-bearing twice over: conform’s format-on-save uses it, and a PostToolUse hook re-runs it on every Lua file Claude Code edits, so the committed tree stays stylua-clean.

It degrades gracefully — a missing stylua means formatting simply does not apply. Edits are never blocked and nothing errors.

.NET (C# and F#)

Guide: .NET Prerequisites

Dependency Purpose Install

.NET SDK

Compiler, dotnet fsi, and the dotnet tool host everything else installs through

Microsoft download page

Microsoft.CodeAnalysis.LanguageServer

C# LSP (Roslyn), driven by roslyn.nvim

Must be on $PATH — see the .NET guide

fsautocomplete

F# LSP; also provides F# formatting

dotnet tool install -g fsautocomplete

csharprepl

C# REPL, driven by iron.nvim

dotnet tool install -g csharprepl

csharpier

C# formatter

dotnet tool install -g csharpier

EasyDotnet

Server tool that easy-dotnet.nvim requires for solution management, run, and test

dotnet tool install -g EasyDotnet

netcoredbg

Debug adapter, auto-registered with nvim-dap by easy-dotnet

A GitHub release binary — not a dotnet tool

netcoredbg is the one .NET tool you cannot get with dotnet tool install. Download the release archive for your platform and put the binary on $PATH.

Haskell

Guide: Haskell Prerequisites

Dependency Purpose Install

ghcup

Installer that manages every other Haskell tool

ghcup

GHC + cabal / stack

Compiler and build tooling; GHCi is the REPL

ghcup install ghc and ghcup install cabal

haskell-language-server

LSP, driven by haskell-tools.nvim (not lua/config/lsp.lua)

ghcup install hls

haskell-debug-adapter

Debug adapter for nvim-dap

cabal install haskell-dap ghci-dap haskell-debug-adapter

Haskell debugging needs both haskell-debug-adapter and an open cabal or stack project. haskell-tools.nvim registers require("dap").configurations.haskell only when it detects a project, so on a bare .hs file the debug configuration list stays empty even with the adapter installed. This is why the Haskell debugging validation step (§7.5 in openspec/TEST_PLAN.md) is deferred rather than failing.

Treesitter parsers

Syntax highlighting, indentation, and the af/if text objects all come from Treesitter, and parsers are compiled from source on your machine. That means a working C compiler is a hard requirement for every language in the table above.

If cc/gcc is missing, parser installation fails and the only symptom you see is a file with no syntax highlighting — nothing announces the missing compiler. See Getting Started → C compiler for the install command and how to verify.

The config installs these parsers automatically on first launch: commonlisp, clojure, scheme, fennel, janet_simple, lua, fsharp, c_sharp, haskell, vim, http, markdown, and markdown_inline. Check the result with:

:checkhealth nvim-treesitter
